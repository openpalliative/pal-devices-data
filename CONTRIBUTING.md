# Как помочь

Спасибо, что заглянули. Здесь лежит перечень медицинских изделий для паллиативной помощи на дому в виде открытых данных и сайт «Кто выдаёт изделия». Помочь можно без программирования: сверить строку со сканом, предложить бытовое название, прочитать тексты глазами юриста или медика

Вклад можно делать под псевдонимом. Соглашений подписывать не нужно

## Главное правило: без личных данных

Issues и PR видят все. Не пишите имена, диагнозы, регион, адреса, телефоны, номера документов, не прикладывайте выписки, ИПРА и скриншоты с ними. Своё дело или дело подопечного здесь не разбираем, для этого есть `obrashchenie-kit` и `/now/` на сайте

Проект не ведёт учёт выдачи, списки подопечных, склады и другие функции учёта. Такие PR не примем

## Чего в данных быть не должно

- бренды, модели, торговые знаки, цены, продавцы и ссылки на магазины
- подбор аппарата, размеры, частота замены, медицинские пороги и советы по лечению
- названия лекарственных препаратов и дозы
- строки по территориям из `opsite/lint/territories.yaml`
- номера, сроки и пункты, которых нет в официальном источнике. Не нашли источник - оставьте `verified: false`, это честнее

Проверки `pytest` ловят часть этого автоматически (знаки товарного знака, цены, латинские модели, территории), но не всё

## Как сверить строку со сканом

Это самый полезный вклад. Перечень опубликован сканом без текстового слоя, поэтому каждую строку сверяют глазами с изображением страницы

1. Найдите строку в `data/398n.csv` (или `data/348n.csv` для прежнего перечня). В колонке `scan_page` номер страницы, в `source_ref` ссылка на источник из `data/sources.yaml`
2. Откройте официальную публикацию: `http://publication.pravo.gov.ru/document/<eoNumber>`, для действующего перечня eoNumber `0001202508130021`. Скачайте PDF и откройте нужную страницу
3. Сравните по скану: код вида (шесть цифр), название вида так, как оно написано в акте (`name_in_act`), группу и подгруппу, отметку сноски 2 (`fn2`)
4. Сравните `nkmi_name` с названием вида в справочнике Росздравнадзора той версии, что в `data/snapshots/nkmi.json`
5. Если всё совпало, страница подписывается в `data/review/scan_pages.yaml`: `eo`, `page`, `codes` (все коды страницы по порядку), `fn2_codes`, `checked_at`, `method` (как сверяли, например «изображение страницы сверено построчно с OCR и НКМИ»)
6. Если не совпало, откройте issue по форме «Ошибка в данных»: код, страница скана, как написано на скане и как у нас. Или PR с правкой строки и ссылкой на страницу

`verified: true` ставится только после сверки с изображением страницы. Сверка со сканом не заменяет проверку юристом: `legal_reviewed` остаётся `false`, пока тексты не посмотрел юрист в России

## Кому что смотреть

- **Медикам:** бытовые названия в `data/aliases.csv` и названия видов в `data/398n.csv`. PR от наблюдателя с меткой `review:medical` ждут именно вас
- **Юристам:** тексты каналов выдачи и предупреждений в `data/channels.yaml` и `data/warnings.yaml`, цитаты в `data/quotes.yaml`. Метка `review:legal`
- **Всем:** бытовое название изделия через форму «Предложить название», чтение карточек вслух человеку старше 60 и рассказ, где было непонятно
- **Разработчикам:** issues с меткой `good first issue`, тесты, доступность

## Как устроены правки

- `data/` правят люди. `data/snapshots/` пишет наблюдатель, руками его не трогайте
- `opsite/` общий для всех сайтов проекта и копируется из хаба `openpalliative.github.io` командой `sh scripts/sync-ui`. Правки в него присылайте в хаб, здесь их перезапишет следующая синхронизация
- `vendor/` это снимки соседних репо, их обновляет `sh scripts/sync-data`
- Перед PR прогоните `sh scripts/gate.sh`: pytest, сборка, проверки сайта, unit и e2e тесты
- Тексты на сайте пишем просто, для человека в стрессе: короткие фразы, без канцелярита, без длинных тире и эмодзи. Статус всегда словом и иконкой, не только цветом

## Ревью

PR смотрит мейнтейнер. Правки `data/398n.csv` дополнительно смотрит человек с медицинским образованием, тексты каналов и цитаты по возможности юрист. Пока мейнтейнер один, обязательного второго ревью нет

Ищем мейнтейнеров в России: юриста и разработчика. Деплой, запуск наблюдателя и любые обращения к российским сайтам делают они. Если готовы, напишите в issue

Поведение в проекте описано в [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), уязвимости сообщайте по [SECURITY.md](SECURITY.md)
