# Безопасность

## Как сообщить об уязвимости

Через закрытый отчёт на GitHub: вкладка **Security** этого репозитория, кнопка **Report a vulnerability** (https://github.com/openpalliative/pal-devices-data/security/advisories/new). Такой отчёт видят только мейнтейнеры

Не пишите об уязвимостях в открытых issue и не прикладывайте к отчёту чужие личные данные. Почты для отчётов у проекта пока нет, личные адреса мейнтейнеров для этого не используйте

Мейнтейнер сейчас один, поэтому быстрого ответа не обещаем. Мы напишем, когда прочитали отчёт, и договоримся, когда о нём можно рассказать публично

## Что считаем уязвимостью

- выполнение чужого кода на страницах сайта, например через поле поиска, фильтр перечня или адрес страницы
- запросы сайта к чужим адресам: сайт должен читать только свои файлы
- утечка того, что человек искал или отметил: в адрес страницы, `localStorage`, cookie, заголовок Referer
- подмена данных в сборке или релизе: `data/v1/*.json`, `_site`, архивы релиза и `SHA256SUMS`
- workflow, который даёт чужому PR или issue запустить код с правами на запись или получить токен

## Что знаем и чего не можем

- Сервера нет, сайт статический на GitHub Pages. Учётных записей и форм отправки нет
- Политика безопасности контента (CSP) задана тегом `meta`: только свои скрипты, стили, шрифты и картинки, `connect-src 'self'`, `form-action 'none'`. Заголовок `frame-ancestors` так задать нельзя, а свои HTTP-заголовки Pages ставить не даёт, поэтому встраивание сайта в чужую страницу технически не запрещено
- Наблюдатель `watch.yml` ходит только к открытым данным Росздравнадзора. Всё, что меняет тексты для семей, идёт через PR и проверку человеком
- Экшены в workflows закреплены по SHA коммита, обновления предлагает Dependabot раз в месяц

## Поддерживаемые версии

Исправления выходят только в ветке `main` и на сайте https://openpalliative.github.io/pal-devices-data/. Старые релизы не обновляются
